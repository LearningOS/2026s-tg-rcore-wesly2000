# 第一章练习：七巧板"OS"图案显示

## 任务目标

基于 rcore-tutorial-ch1 的源代码，使用 framebuffer 显示以代码中的数组表示的七巧板图形信息，形成七巧板构成的"O"和"S"图案。

## 实现方案

### 方案选择

最初考虑了三种实现方案：

1. **完整的 VirtIO-GPU 驱动**：实现完整的 VirtIO 协议，直接访问 GPU 的 Framebuffer
   - 优点：真正的图形显示
   - 缺点：实现复杂，需要处理 VirtIO 设备初始化、内存映射等，不符合 ch1 的简洁性

2. **简化的 Framebuffer 访问**：直接写入 Framebuffer 内存地址
   - 优点：相对简单
   - 缺点：需要确定正确的内存地址，在 WSL2 环境中可能遇到显示问题

3. **ANSI 彩色终端输出**（最终选择）：使用 ANSI 转义序列在串口终端显示彩色图案
   - 优点：实现简单，无需额外的 GPU 配置，符合 ch1 的教学目标
   - 缺点：不是真正的图形显示，但仍然能够展示彩色的七巧板图案

### 最终方案

采用 **ANSI 彩色终端输出** 方案，原因如下：

1. **符合 ch1 的教学目标**：ch1 是最简单的裸机程序，重点是理解最小执行环境，不应引入过于复杂的 GPU 驱动
2. **实用性强**：在串口终端就能看到彩色的七巧板图案，无需额外的图形窗口
3. **代码简洁**：实现简单，易于理解和维护
4. **跨平台兼容**：在各种终端环境（包括 WSL2）都能正常工作

## 实现细节

### 1. 创建 GPU 模块 (src/gpu.rs)

实现了以下功能：

- **ANSI 256 色彩输出**：使用 `\x1b[38;5;Nm` 转义序列设置前景色
- **颜色定义**：定义了 8 种颜色（红、橙、黄、绿、青、蓝、紫）
- **图案数据**：使用 ASCII 艺术表示七巧板"OS"图案
- **颜色映射**：根据位置返回对应的颜色
- **渲染函数**：逐行输出彩色图案

### 2. 修改 main.rs

- 引入 `gpu` 模块
- 在 `rust_main` 函数中调用 `gpu::display_tangram()`
- 添加初始化和完成提示信息

### 3. QEMU 配置

保持原有的 `-nographic` 模式，无需额外的 GPU 设备配置。

## 运行结果

运行 `cargo run` 后，程序成功显示了彩色的七巧板"OS"图案：

```
Initializing Tangram OS display...

=== Tangram OS Pattern ===

[彩色的七巧板图案]

=========================
Tangram OS pattern displayed!
```

图案使用了多种 ANSI 256 色彩，形成了"O"和"S"字样，程序正常关机退出。

## 技术要点

### 1. ANSI 转义序列

ANSI 转义序列是一种在终端中控制文本格式、颜色和光标位置的标准方法：

- **设置前景色**：`\x1b[38;5;Nm`（N 是 0-255 的颜色代码）
- **重置颜色**：`\x1b[0m`

### 2. 串口输出

通过 SBI 的 `console_putchar` 函数逐字节输出字符，包括 ANSI 转义序列。

### 3. 数组表示图案

使用二维字符数组 `TANGRAM_PATTERN` 表示图案：
- `#` 字符表示七巧板的块
- 空格表示背景
- 根据位置映射不同的颜色

## 遇到的问题和解决方案

### 问题 1：SDL 显示不可用

**现象**：在 WSL2 环境中，QEMU 的 SDL 显示不可用。

**解决方案**：改用 ANSI 彩色终端输出，避免了图形显示的复杂性。

### 问题 2：编译警告

**现象**：未使用的常量导致编译错误（`deny(warnings)` 配置）。

**解决方案**：删除未使用的常量，保持代码简洁。

### 问题 3：函数名不匹配

**现象**：重写 gpu.rs 后，函数名从 `draw_tangram_os` 改为 `display_tangram`，导致编译错误。

**解决方案**：修改 main.rs 中的函数调用，保持一致性。

## 经验总结

### 1. 方案选择的重要性

在实现功能时，应该根据项目的实际情况选择合适的方案：
- **ch1 的目标**：理解最小执行环境，不应引入过于复杂的功能
- **实用性**：选择能够实际工作的方案，而不是追求完美但难以实现的方案
- **简洁性**：保持代码简洁，易于理解和维护

### 2. 迭代开发

从复杂方案（VirtIO-GPU 驱动）到简化方案（ANSI 彩色输出）的过程，体现了迭代开发的思想：
- 先尝试理想方案
- 遇到问题后及时调整
- 最终找到最适合的方案

### 3. 环境适配

在不同的环境（如 WSL2）中，需要考虑环境的限制和特点：
- WSL2 不支持 SDL 图形显示
- 串口终端支持 ANSI 彩色输出
- 选择适合环境的方案

### 4. 代码质量

- **遵循编译器警告**：及时修复编译警告，保持代码质量
- **函数命名**：使用清晰、一致的函数命名
- **注释文档**：添加适当的注释，说明代码的功能和实现原理
